# 🚀 EasyESP Connect v1.0.0 (Initial Release)

Welcome to the first official release of the **EasyESP Connect** Kotlin Multiplatform (KMM) Library and ESP32 Firmware companion! This release provides a battle-tested, resilient end-to-end framework for provisioning ESP32 devices to a local Wi-Fi network from Android apps.

## 📦 What's Included?

### 1. Kotlin Library (`:shared`)
*   **Automated Device Discovery**: Uses Android's `WifiManager` to passively scan for local ESP32 devices broadcasting setup SSIDs.
*   **`WifiNetworkSpecifier` Integration**: Programmatically binds Android OS networking routes to the ESP32's temporary hotspot (`AndroidHotspotConnection`).
*   **Cleartext HTTP Routing Fixes**: Bypasses Android 9+ Cleartext restrictions and forces `ConnectivityManager` to route HTTP requests over Wi-Fi instead of Cellular data.
*   **Jetpack Compose UI Flows**: Ready-to-use Compose states (`EspUiState`) spanning 11 unique connection states, handling Android OS timeouts, user manual fallbacks, and Wi-Fi scanning latencies.

### 2. ESP32 Firmware (`esp32_wifi_setup.ino`)
*   **Dual Mode (`WIFI_AP_STA`)**: Allows the ESP32 to act as a configuration portal (`EasyEsp-Setup`) while simultaneously scanning the environment for home routers.
*   **Open Network Configuration**: Bypasses strict WPA2 minimum-length bugs found in some Android OS distributions.
*   **NVS Wi-Fi Clearing**: Built-in memory flushing (`WiFi.disconnect(true, true);`) to prevent the ESP32 from hanging on older saved network states.
*   **Synchronous WebServer Endpoints**:
    *   `GET /networks` - Retrieves surrounding Wi-Fi networks and RSSI signal strengths in JSON format.
    *   `POST /credentials` - Handles the target `ssid` and `password` payload to initiate local connection.

## 🛠️ How to Implement

### Android (KMM Integration)
Add the `:shared` module as a dependency to your Android application:
```kotlin
// In your app/build.gradle.kts
dependencies {
    implementation(project(":shared"))
}
```

Ensure your `AndroidManifest.xml` includes the necessary networking/location permissions and **Cleartext traffic flag**:
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
<uses-permission android:name="android.permission.CHANGE_WIFI_STATE" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<uses-permission android:name="android.permission.CHANGE_NETWORK_STATE" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

<application
    android:usesCleartextTraffic="true"
    ...>
```

**1. Pure Compose (with automatic ViewModel integration):**
Just drop the built-in composable in your UI. It takes a configuration object and success/error callbacks.
```kotlin
import com.easyesp.shared.ui.EasyEspSetupUI
import com.easyesp.shared.mvi.EasyEspConfig

@Composable
fun MyScreen() {
    EasyEspSetupUI(
        config = EasyEspConfig(scanTimeoutMillis = 30_000L),
        onSuccess = { println("Provisioning Success!") },
        onError = { println("Provisioning Failed: $it") }
    )
}
```

**2. Activity Result Contract (for non-Compose or easy fragment integration):**
If you want to just launch the flow and get a callback without dropping the composable:
```kotlin
import com.easyesp.shared.ui.EasyEspSetupContract
import com.easyesp.shared.mvi.EasyEspConfig

// In your Activity or Fragment
val easyEspLauncher = registerForActivityResult(EasyEspSetupContract()) { result ->
    result.onSuccess { 
        println("Provisioning Success!") 
    }.onFailure { 
        println("Provisioning Failed: ${it.message}") 
    }
}

// Launch the UI
easyEspLauncher.launch(EasyEspConfig())
```

**3. Code-Only MVI Implementation:**
If you want to implement your own UI, we provide an MVI (Model-View-Intent) Session. Send `EasyEspIntent`s and observe `EasyEspState`:

```kotlin
import com.easyesp.shared.EasyEsp
import com.easyesp.shared.mvi.*

// Create an MVI session
val session = EasyEsp.createSession(context, coroutineScope, EasyEspConfig())

// Observe the state flow
lifecycleScope.launch {
    session.state.collect { state ->
        when (state) {
            is EasyEspState.Discovering -> showLoader()
            is EasyEspState.EspDevicesFound -> updateList(state.devices)
            // ... handle all other states ...
        }
    }
}

// Send intents
session.sendIntent(EasyEspIntent.CheckPreconditionsAndStart)
```

### ESP32 (Firmware Deployment)
1. Open `firmware/esp32_wifi_setup.ino` in Arduino IDE.
2. Ensure you have the [ESP32 board package](https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json) installed.
3. Select your ESP32 board and upload at `115200 baud`.

## 🛣️ Roadmap & What Else You Can Do

The foundational communication pipeline between the Android device and the ESP32 is now established. Because you are using **Ktor** and a standard **HTTP WebServer**, this library can easily be extended for:

1.  **Custom Sensor Data Real-Time Streaming**: Add a `GET /sensor-data` endpoint on the ESP32 to stream temperature/humidity data directly into the Compose app while connected to the hotspot.
2.  **OTA (Over-The-Air) Firmware Updates**: Use Ktor to upload a `.bin` file directly from the Android app to an ESP32 `POST /update` endpoint.
3.  **Local Device Control**: Add a `POST /toggle-led` endpoint to control relays or lights locally without needing a cloud server (MQTT/Firebase).
4.  **Bluetooth LE (BLE) Provisioning Migration**: In future updates, the underlying `DeviceDiscovery` interfaces in `:shared` can be swapped from Wi-Fi Hotspot provisioning to BLE (Bluetooth Low Energy) provisioning, yielding an even faster user experience.
